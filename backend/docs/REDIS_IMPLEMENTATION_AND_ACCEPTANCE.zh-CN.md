# Redis 一天面试实战：实施与验收

基线：`2a45d2a`，独立分支 `feature/redis-interview`。保留原项目未提交的Qwen/评测工作；完成后将Redis增量同步到原工作树并分别说明集成状态。前后端原生启动，Redis独立服务；Docker不是测试前提。

## 阶段一：连接、缓存、故障回源与观测

实现：共享异步Redis客户端、有限连接/超时且不自动重试非幂等命令；政策分类树Cache Aside、schema校验、短TTL抖动、进程内冷请求合并、管理员提交后失效；默认分类fallback不可缓存；管理员状态/计数接口。

验收标准：

1. Redis关闭/未启用时保留原功能，正常读可回源。
2. 真实Redis首次MISS、再次HIT且内容一致；TTL到期重新加载。
3. 多个冷请求同进程合并加载，JSON损坏不污染响应。
4. 修改分类后跨API实例下一读为新值；简单TTL仍有旧读晚回填边界，文档明确。
5. 数据库fallback不写Redis；写失效失败不伪报数据库保存失败。
6. 指标接口只允许管理员，不返回Redis URL/凭据；所有资源在lifespan关闭。
7. 阶段相关单元/真实Redis集成与既有回归通过后提交。

## 阶段二：Lua限流、入口保护与多实例

实现：按认证user_id的固定窗口原子准入；chat与stream共享规则，resume/upload独立；超额429，Redis故障昂贵入口503；准入先于模型/消息/任务副作用及SSE响应；仅开发且显式开启的管理员演示入口。

验收标准：

1. 真实Redis、两个原生API实例、同用户40并发，规则10次窗口内总计10次成功/30次429。
2. 用户B额度独立；规则窗口到期恢复，拒绝不延长窗口。
3. 未登录401、普通用户不能访问管理员调试；生产环境演示入口404。
4. 真实chat/stream/upload拒绝时不创建业务记录、不调用模型。
5. Redis通信/脚本失败503且不自动重复扣额；默认关闭不破坏原测试。
6. 单元、实际Redis并发和真实HTTP验收通过后提交。

## 阶段三：独立用户旅程、量化与交付

实现/验证：独立agent测试真实登录/邀请/注册、PDF上传/重放/提取/向量/下载、多账号并发读取；缓存开/关多轮AB/BA对照；Redis停止/恢复；提供一键验证、日志和入门文档。

验收标准：

1. 真实PDF完成索引，原文唯一标识和预算数值保留，向量维度/数量正确，下载SHA一致。
2. 多账号并发读成功；原有资料不删除，脚本只清理自己的账号/文档，前后摘要相同。
3. 同数据同机器同鉴权路径，报告请求数、并发、错误率、P50/P95和分类loader调用数；热缓存loader应为0，基线每请求加载。不预设延迟一定提升。
4. Redis宕机时分类有界回源，昂贵准入503；恢复后HIT/额度正常。
5. 最终回归、静态检查和原工作树兼容测试通过；按阶段提交并推送正确仓库分支。

## 结果与边界

实施结果、具体测试数和量化数据在完成后追加。分类loader调用数不是全部SQL数，认证仍查数据库。限流不是Token财务账本，缓存不跳过权限。PostgreSQL任务、幂等、租约保持权威；本次不迁移broker、不做语义答案缓存。
