记录日期：2026-10-23。该文档记录本机实际执行结果；旧的 Qwen 安装记录中的 512/64 是起始配置，当前应用的配置以本文为准。原始逐题输出保留在数据库和 `backend/eval-results/experiment-v2/`，该目录被 Git 忽略，避免把大体积实验数据提交到仓库。

## 2. 手动迁移和数据库核验

实际执行了 `python -m scripts.migrate_evaluation`，只应用增量迁移 029、030，未执行会重置主体数据库的 init.sql。

迁移脚本使用事务级 advisory lock，并在 `app_schema_migrations` 记录文件 SHA256。再次执行时 `applied=[]`，九张评测／校验相关表全部存在；已执行迁移文件若被改写，会拒绝重复应用。

参数应用后通过既有持久化任务队列完整重处理了 **19 份文件**，包含原有 7 份和官方测试 12 份：

- 19 份文件全部 ready，文件 ID 集合保持一致。
- 原先 835 个 chunk 被替换，当前 **499 个 chunk / 499 条 Qwen 向量**。
- 重建前后的 chunk ID 交集为 **0**，未混用旧 chunk。
- 当前实际 `token_count` 最大值为 **768**。
- 测试 12 份文件的 **383 个 chunk**，其文本、页码范围和 token 数与胜出的实验索引逐条完全一致。
- 每份文件取一个 chunk，重新运行真实 Qwen Embedding，与数据库向量比较；19 个样本最小余弦相似度 **0.9997683**。BF16、batch 差异下使用 0.999 的容差。

这既验证了重新切块，也验证了实际更新向量，未只依据接口返回“成功”判断迁移完成。

题目位于 `app/modules/evaluation/data/cases-v2.json`，版本 2.1，共 **73 个可回答正例、47 个应拒答反例**。旧版 27 题继续保留。

| 类别 | 数量 | 目的 |
| --- | ---: | --- |
| F：原文事实题 | 48 | 每份文件四个有页码、短原文锚点的事实 |
| S：错误文档范围 | 12 | 把正确问题交给不包含依据的文档 |
| U：未提供的具体结果 | 12 | 区分目标／建议与实际测量、承诺、具体产品数据 |

| C：多个必答要求 | 12 | 相近及不同领域的联合问答 |
| M：缺少一侧来源的配对题 | 12 | 检测部分回答被错误当作完整回答 |

M07 是特殊正例：虽然没有选原始 CSF PDF，但选中的 NIST incident-response 文档第 13 页也完整列出了六个 CSF Functions。题集已经接受这个同等权威的替代依据，不能因为“没有选指定原文件”就判拒答。

正例按 requirement 定义答案要点，每个要点允许多个合法的 source/page/quote alternatives。Recall 是满足多少个必答要求，不是命中了多少个重复 chunk。反例不计算无意义的正例 Recall。

calibration 48 题、validation 48 题、diagnostic 24 题。参数选择只读取 calibration；validation 与 diagnostic 用来展示差异。它们仍来自同一文档集，部分诊断事实也出现在事实题中，并且后续协议调试看过输出，因此不能声称是外部盲测或独立生产分布。

## 4. Budget / overlap 先做，不能凭经验指定

分块实验使用真实 Qwen tokenizer、真实本地 embedding 和 reranker。每组只写实验专属索引表，不覆盖生产文库。关闭 LLM context header，避免把模型生成标题的收益和分块收益混在一起。

过程中发现旧 chunker 把段落／句子各自的 token 数相加，忽略拼接后的 token 数不一定可加。曾出现配置 256、实际达到 280 token。两次中间实验已取消保留，不参与选参。修复后按实际拼接文本计数，必要时缩短 overlap；所有十二组实际最大长度均未超过预算。

## 5. Top-K / threshold 的依据

对胜出的索引回放 `4×2×6×4=192` 组：Top-K 4/6/8/12，文档配额开关，距离 0.30/0.35/0.40/0.45/0.50/0.60，reranker 下限 0.20/0.50/0.80/0.95。

选参顺序是：保留完整证据覆盖、保留 requirement Recall、减少弱候选通过、减少上下文 token。选择 Top-K=4、quota=true、distance=0.60、floor=0.20 后：

- calibration 与 validation 正例完整证据覆盖均为 100%。
- calibration 平均候选上下文由 3412 降为 1450 token；validation 由 3460 降为 1698 token。
- diagnostic 完整覆盖为 69.2%，暴露了多要求问题只用固定全局排序的不足。
- 即使采用该阈值，calibration 仍有 6/18、validation 有 11/18 个反例存在“相关片段”。**相关性不能证明可回答性。**

回放只复现候选分配和分数门槛，不包括实时子问题改写、answerability、最终生成及 claim 校验。实时完整链路必须另测，不能把回放结果当成最终正确率。

## 6. 当前的证据保护

1. 提取问题的全部必答要求；有数量上限且无法完整表达时拒绝静默截断。
2. 对多个要求分别检索，在同一已选文档范围内补候选；为文档和子问题预留候选位置。
3. answerability 为每个要求返回答案事实和原文摘录。仅仅相关、提到另一份出版物、只有比较的一侧、把目标当成实测，均不足以放行。
4. Writer 只回答请求的事实，减少未要求的背景和建议。保留时间、单位、例外、适用主体与法律效力差别。
5. 完整草稿按确定性规则分为 C1/C2 等单元，逐个检查其全部主张；任一 unsupported 单元阻止最终回答。
6. 代码检查 ID 覆盖、引用编号、当前数据库 chunk 身份、文档范围、逐字摘录；数字存在性只作补充检查，不代替语义蕴含判断。
7. 协议错误可以纠正重试一次，例如把 C1 擅自改成 C1a，或摘录拼接了不连续原文。重试也必须满足相同检查，不会直接豁免失败项。
8. Direct 和 ReAct 的 Document Analysis 都在校验完成前缓冲草稿，不提前发送未经检查的 token。失败／超时保持拒答；预算用尽作为预算停止处理，不伪装成反例通过或证据不足的测试结论。

短摘录可能没有重复文件标题中的“CSF 2.0”，因此补充的数字存在性检查针对实际引用 chunk 和标题，不要求每个版本号必须再出现在模型选择的短摘录里。英文 three/six 等词也不能靠字符串出现来验证列表计数；数量、单位和条件的实际关系交给 claim 语义校验。

## 8. 为什么使用 LLM-as-a-Judge，以及为什么不能迷信它

强模型按参考要点和证据为另一模型打分，通常叫 **LLM-as-a-Judge**。本项目采用 reference-guided judging：groundedness、completeness、citation support 各 0–4，并单独记录 uncertain、理由和不受支持的主张。总分是 40 分决策正确性加三维各最多 20 分；保留各维，不只保留一个总分。

该思路在 [MT-Bench / Chatbot Arena 论文](https://arxiv.org/abs/2306.05685) 中有系统研究；RAG 中的多维自动评估可参考 [RAGAS 原论文](https://arxiv.org/abs/2309.15217)。模型裁判适合扩展回归评测，不能被当作验证过的事实真值。生成与裁判来自同一模型家族，还可能共享偏差。

本次审查已经出现具体反例：强模型找出了 M07 的错误负标签；但也两次把不连续片段拼成所谓逐字引用，并曾把 C03 中仅属于第二个要求的 Australia 错误扩展到第一个要求，从而误判 UK 风电目标不可回答。程序化摘录检查和人工可核对的参考锚点仍有必要。

因此人工 review 是可选复核入口，不是每题强制环节；自动分数、原文、失败原因及不确定项均可追溯。不能因为裁判模型更强，就把评分当成无误的事实认证。

## 9. 删除了哪些关键词规则

删除普通问句中的年份／地区／语言／“最新”自动推断。复现过的问题包括：

- 把“2030 年目标”误当成“2030 年发布的文件”。
- 中文年份边界不识别，双边年份区间丢失下界。
- 否定表达仍把被排除的国家加入筛选；英文地区名没有单词边界。
- “最新”固定映射近五年，并不能证明仍然有效。
- 文档仅提到某国就算满足地区证据覆盖。
- 显式筛选失败后自动扩大范围，放入不符合用户要求的来源。

保留用户主动填写的结构化元数据过滤条件，按元数据精确过滤；没有匹配项就明确失败，不扩范围。自然语言中的适用地区、政策目标年份、有效性要求继续由覆盖契约和语义证据校验处理。没有删除 BM25。

## 10. Token 约束：已经落地的默认值

用户提出成本限制时，已取消最新付费运行，52 个已完成输出保留。当时记录到的历史用量去重下限：Pro 600 次、3,164,760 token；Flash 1008 次、2,097,634 token。旧非保护生成、部分失败及取消时在途请求可能未记录，不能当作账单精确值。

| 成本设置 | 当前默认 |
| --- | --- |
| 回答模型 / 可选评分模型 | DeepSeek V4 Flash / Flash |
| 额外 LLM judge | **关闭** |
| 每次付费批次题数上限 | **20**，按类别／split 轮流采样 |
| 每次付费运行预估 token 预算 | **100,000** |
| API 请求数上限 | **40，包含重试** |
| 单次输入预估上限 | **20,000** |
| 完整文档审查 | **默认关闭，必须显式开启** |
| 输出上限 | plan 600；answerability 1600；回答 800；claim 校验 3000；可选 judge 800 |

预算通过 ContextVar 在异步任务与工作线程间共享同一带锁计数器。发送前预留输入与最大输出额度，每次重试重新预留。预算用尽后禁止发下一次请求；已完成结果保留，未执行题目不算通过／失败。模型服务的隐式自动重试在受限生成路径中关闭，避免绕过调用计数。

**预估 token 预算采用 UTF-8 字节数加消息开销，故意偏保守，不是 DeepSeek 官方 tokenizer 或财务配额。** 因而可能不到 20 题就停止。额外提供严格的 API 次数限制，并保存服务端实际报告的 input/output/total usage。它限制本项目评测运行，不能限制用户在其他应用或同一账号其他进程中的花费。

本次成本控制部署后没有再发新的付费 LLM 测试。预算、线程共享、重试、默认关闭评分等行为使用假模型与隔离 PostgreSQL 测试验证；新的较低输出上限尚未再做完整 120 题实测。

## 11. 页面复现和续跑

Management → Evaluation & scoring：

1. 本地分块及 overlap 比较，或一键运行分块→参数网格；这两步不调用付费 LLM API。
2. 在参数运行中点击 Apply selected configuration & rebuild Library，等待文库处理结束。
3. 检查模型、题数、预算、是否启用额外评分，再启动有预算的回答批次。
4. 从已取消／未完成的运行点击 Run unfinished cases only。续跑引用原运行，不复制旧输出；会累计跳过原运行及之前续跑批次已经完成的题目。索引／证据设置改变则拒绝混用旧结果。
5. 可查看逐题答案、引用、覆盖检查、claim 校验、可选分数，以及冻结配置；导出完整 JSON。

不再默认启动 Pro 裁判或 120 题全量付费测试。完整文档审查通常输入非常大，除开关外还需要预算允许，不能通过一次按钮绕过预算。

命令行可复现：在 backend 目录使用项目 `.venv` 执行 `python -m scripts.run_evaluation_experiment`。该脚本现在继承页面保存的 Flash／预算／评分开关，未硬编码 Pro。`status --id UUID` 只读导出；`python -m scripts.audit_evaluation_usage` 只读统计历史用量，不调用模型。
