# 数据库运行故障定位与修复（2026-10-15）

## 问题在哪里

项目 `backend/.env` 配置的是本机 `localhost:5432/testdb`。检查发现，这个库有原来的用户、文档、向量等表，但缺少第二阶段新增的两张表：

- `document_tasks`：保存后台处理任务及租约、重试次数等状态。
- `document_upload_requests`：保存上传请求的幂等键与文档、任务的对应关系。

使用这个配置实际启动后端，复现了以下错误：

```text
Document worker polling failed
psycopg.errors.UndefinedTable: relation "document_tasks" does not exist
```

数据库能连上，也能查询原来的文档。错误出在“新代码需要的表还没有在当前数据库创建”。原来的启动过程只验证连接，随后就启动 worker。于是服务显示启动成功，worker 却每秒查询不存在的表，持续打印异常，任务列表和上传登记也会受到影响。

此前保留运行的演示服务连接的是 `127.0.0.1:55432/step2_e2e_tests` 隔离测试库，与项目 `.env` 的库不同。浏览器访问该演示服务时，项目原有账号和登录令牌可能无法使用。这次已停止该演示 API 和独立 worker，将 8000 端口后端切回项目 `.env`，前端仍通过 3000 端口代理访问它。

## 这次修复了什么

1. 对项目原有 `testdb` 做了完整备份，再运行已有的 **028 号增量迁移**。
2. 新增迁移入口，在 `backend/` 下运行：

   ```powershell
   python -m app.modules.documents.migrate
   ```

   它读取与服务相同的 `.env` 和环境变量，先显示数据库地址与库名，不显示凭据。建表、索引和未完成文档的任务补登记放在同一个事务中。发生错误时一起回滚，并用数据库锁串行化同时执行的迁移。

3. API 和独立 worker 启动时检查上述两张表。缺表时直接停止启动，错误信息指出缺失表和修复命令。这样不会把无法处理任务的服务当成启动成功，也不会让多个 worker 持续刷相同错误。
4. 增加回归验证：缺表时阻止两种服务启动并关闭连接、迁移保留数据、重复执行不重复补任务、迁移失败时回滚已执行的建表操作。

## 真实上传又发现了什么

补齐数据库后，真实 PDF 上传能返回 202、任务能领取、心跳能续租，但处理停留在 `parsed` 或 `annotated`。通过运行进程的线程栈确认，有两处在等外部模型的 HTTP 响应：生成文档元数据，以及生成文本块的上下文说明。数据库连接此时是空闲的。

原来这两处没有指定请求超时、重试次数和输出长度。即使说明文字只需要一句话，也可能等待模型服务几分钟。第一次完整验证等待 180 秒仍未完成，暴露了这个问题；它不能算验证成功。

本次为这两项可选增强增加了等待预算：

| 可选增强 | 网络超时 | 等待结果上限 | 最大输出 token | SDK 自动重试 |
| --- | --- | --- | --- | --- |
| 文档元数据生成 | 15 秒 | 模型调用阶段 30 秒 | 1024 | 0 |
| 文本块补充说明 | 10 秒 | 整批说明阶段 20 秒 | 128 | 0 |

元数据超时会触发已有的默认元数据回退；某个文本块未能及时取得说明，就用原文继续生成向量。保留已及时完成的说明，并保持文本块顺序及原文不变。元数据请求使用共享的 3 线程池，限制同时运行的慢请求数。

网络超时是连接、读取等网络操作的等待限制，不是整份文件的总时长。因此另设等待结果的阶段上限。Python 线程不能被强行取消；阶段超时后丢弃迟到结果，尚在运行的 HTTP 请求仍受自身网络超时约束。这些限制针对上传过程中的可选增强，用户正常聊天的客户端默认参数未修改。

如果外部模型持续不可用，自动生成的标题、摘要或补充说明可能退回默认内容。文件原文、分块和向量索引仍应完成；外部向量服务自身不可用时，持久任务仍按现有策略重试。

**这条命令只处理 028 号迁移。** 全新数据库仍按 README 初始化；更早版本仍需先补齐之前的迁移。启动检查针对这次缺失的两张表，不是所有历史表结构的完整审计。

已有数据的数据库不要重新执行 `database/init.sql`，该文件包含重建表操作。此次没有使用它。

## 以后遇到相似报错如何判断

- `UndefinedTable`：代码使用了当前库没有的表，核对库名及迁移是否执行。
- `UndefinedColumn`：表存在，但某个字段缺失，核对相关字段迁移。
- `connection refused`：目标端口没有数据库服务监听，先核对服务和连接地址。
- 登录返回 `401`：先看服务是否连到预期的数据库、令牌是否属于当前服务，再核对账号密码。

连接池只能复用数据库连接，不能自动创建业务表。把连接池开大也无法解决这次错误。
